# 设计决策

## D1. Vite 8 + React 19，而不是 Next.js

项目是单页、单用户、无 SSR 需求的私人应用。Vite 开发启动快，生产只需静态资源 + 一个 Node 进程；Next.js 的路由、RSC 与服务端渲染能力在这个规模下是额外复杂度。

## D2. Node 原生 HTTP，不引入后端框架

路由数量有限（认证 6 条、卡片 4 条、裁切模式 3 条、图片 2 条），用 `node:http` 即可保持依赖最小、启动最快，也便于直接阅读请求链路。代价是需要自己实现 JSON 解析、Cookie 与静态资源服务，这些集中在 `apps/server/src/http.ts` 与 `apps/server/src/index.ts`。

## D3. `@homurajs/db` + Drizzle + `node:sqlite`

满足「所有数据用 `@homurajs/db` 与 `node:sqlite` 持久化」的硬性要求，同时保留迁移、类型与 SQL 能力。SQLite 单文件适合私人收藏；WAL 提升并发读，`busy_timeout` 减少锁冲突。

## D4. 腾讯网页 QQ 扫码，而不是自建 OAuth 应用

用户明确希望走腾讯网页登录、直接拿唯一 QQ 号，避免配置应用凭据。服务端代理 `ptqrshow` / `ptqrlogin`，只保存 `qrsig` 与 `ptqrtoken`。风险是该公开接口可能调整；官方 QQ 互联 OAuth 作为可选后备保留。

## D5. 手牌环在屏幕平面内，而不是 3D 圆柱

用户明确纠正：牌环平面必须与屏幕平行，像人手拿扑克牌。实现为「圆心在下方的大圆弧 + 每张牌绕圆心旋转」，而不是 `rotateY + translateZ` 的 3D 轮播。这样所有卡面都正面朝向用户，叠压关系也更像手牌。

## D6. 固定可视槽位 + 循环队列

如果直接用 `360/n` 的整圆分布，牌少时会只剩一两张可见，牌多时又会挤成一条线。采用「最多 5/7 个可视槽位 + 卡片循环映射」：静止时整扇手牌都在，卡片尽可能大；转动时卡片从两侧隐藏区循环进出，并在边界外半格完成淡出/淡入。

## D7. 彩光常驻且低透明度，陀螺仪驱动

用户希望彩光默认存在但非常淡，并随手机姿态移动光斑。实现为常驻的 `mix-blend-mode: color` 彩带 + 跟随 `--hx/--hy` 的径向光斑；摇一摇只做临时增强，而不是唯一的触发方式。`color` 混合在浅色卡面上仍能显色，避免 `color-dodge` 在亮图上几乎不可见。

## D8. 叠放交给手牌顺序，不强行让中心牌置顶

中心牌永远置顶需要每帧重排 z-index，既昂贵又会造成卡片跳层。改为按槽位从左到右固定叠放，右侧压左侧；中心牌被遮住是正常的，用户点击露出的部分即可端详。

## D9. 图片以 BLOB 入库

私人应用、单文件备份、数量有限，BLOB 比对象存储更简单，也满足「所有数据持久化在 SQLite」的要求。列表接口只查元数据，避免把图片带进首屏 JSON。

## D10. Playwright E2E 作为验收

E2E 使用真实构建、真实 Node 服务、真实 SQLite 与合成卡面照片，覆盖登录门禁、自动识别拉正、正反面、持久化、删除、拨动/停驻、上滑端详、翻面与彩光。测试端口 4318、数据目录 `.e2e-data`，与开发数据隔离。

## D11. 暖粉拟物主题

用户要求整体配色「多用粉白、温馨可爱、不要商务正式」。主题以奶油白、樱花粉、玫瑰金为基底，标题使用宋体保持精致感，界面使用系统无衬线字体；纸张、和纸胶带、缝线边框与柔和投影构成拟物细节。登录页收敛为一张扫码纸卡。

所有带色相的颜色统一落在 343°–356° 的粉红区间（原 320°–345° 的洋红调会被看成偏紫），低饱和的深色文字同步提高饱和度转为暗玫瑰，浅色纸面保持 B 分量只比 G 高约一个 delta/6，避免发白时重新偏冷。奶油色面板与镀层彩虹光作为暖色对照保留，不参与这一约束。

## D12. 镀层作为每张卡的显式开关

彩光从「所有卡常驻」改为「只有开启镀层的卡才显示」，默认关闭。私人收藏里不同卡片的工艺差异很大，普通卡强行覆一层镭射光会显得失真；把选择权交给收藏者，也让新增/编辑表单多一个可控的外观维度。数据库用 `holo` 整数列（0/1）而不是布尔类型，保持与 SQLite + Drizzle 现有写法一致；迁移带默认值 0，已有卡片自动保持无镀层。

## D13. 端详只认显式关闭，界面默认不可选中

端详是一张卡的阅读态，误触背景就退回牌山会让收藏者丢失正在看的位置，因此只保留右上角关闭按钮与 `Esc` 两条退出路径。

应用整体按「原生质感面板」处理：`html/body` 关闭 `user-select` 与 `-webkit-touch-callout`，只对 `input`、`textarea` 与可编辑元素恢复文本选中。文字是界面的材质而不是可摘取的文档，长按弹出系统选词框会打断端详的沉浸感。
品牌徽记改为一枚卡牌扇形叠放的线描图标：字母缩写在小尺寸下容易糊成一团，也缺乏收藏主题的指向。

## D14. 登录会话默认永久

单用户私人应用的使用频率低，30 天固定过期会造成频繁重扫二维码。会话行默认写入 9999 年的 `expires_at` 哨兵，保持现有 SQL 过期判断不变；Cookie 受浏览器 400 天上限约束，因此每次 `GET /api/me` 都重新下发 400 天 Cookie，常用设备上等价于永久。切换到永久模式时，未过期的旧会话会在启动时一并延长，已登录设备无需重扫。代价是 token 不再自然轮换，泄露后只能通过登出或清空 `sessions` 表失效；如需恢复固定期限，设置 `SESSION_DAYS=30`。

## D15. pnpm workspace 目录形式

为了与 node-mono-starter 的工程形式对齐，仓库改为 `apps/server`、`apps/web`、`packages/shared` 三包：根目录只保留工作区脚本、Playwright 与共享配置，前后端各自声明依赖。`@cardvault/shared` 以 TS 源码直引，由 Vite 解析、由 tsup 内联，避免额外的构建步骤。服务端开发时仍直接运行 `src/index.ts`（Node 26 原生剥离类型），生产用 tsup 产出 `apps/server/dist/index.js`；`PACKAGE_ROOT` 由模块位置推导，源码与 bundle 共用同一套 `.env`、数据目录与迁移路径。技术栈保持 D2/D11 的取舍不变。

## D16. 未发版前的迁移合并

项目尚未发布，保留三段增量迁移只会让首次部署多执行两次 `ALTER`。把迁移重置为单一初始迁移（包含 `holo`、`qrsig`、`ptqrtoken`、`qq_uin` 全部列），本地开发库按新迁移重建，旧库已备份为 `data/vault.db.bak-20261018`。迁移目录随服务端移动到 `apps/server/drizzle/sqlite`，继续由 `pnpm db:generate` 维护。

## D17. 移除 Origin 同源校验

最初在 `http.ts` 里用 `PUBLIC_URL` 白名单校验写请求的 Origin。部署到局域网 IP 后，浏览器 POST 携带的 Origin 与默认的 `http://localhost:52188` 不一致，取码接口被判 `cross_origin`，页面能打开但二维码请求 403。单用户私人应用的 CSRF 实际由 `SameSite=Lax` 的 HttpOnly 会话 Cookie 承担（跨站 POST 不携带 Cookie），JSON 写接口也无法被简单表单跨站提交，因此该校验是冗余的，还强制 `PUBLIC_URL` 与实际访问地址严格一致。移除 `assertSameOrigin` 后，「后端代理腾讯二维码」不再依赖站点地址配置；`PUBLIC_URL` 仍用于 QQ 回调与 Secure Cookie 判定。

## D18. 自定义裁切模式只保存归一化四角

用户有大量同一拍摄位置、同一裁切策略的照片，每次重复拖四角不现实。模式保存四个角的归一化坐标（`0..1`）而不是示例照片或像素坐标：像素坐标绑定图片尺寸，换一张分辨率不同的照片就失效；保存照片则让模式变成第二个图片库，备份体积和权限面都扩大。归一化坐标可以直接跨宽高比复用，正好对应用户所说的「四个落点在图里的相对位置」。模式存在 `crop_presets` 表并随用户级联删除，前端在「整图」右侧列成快捷按钮，点击即替换四角；手动拖动或重新识别会取消当前模式的高亮，避免误以为仍在套用。
